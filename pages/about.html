About SkillSwap & Viva Guide

Tagline: "Learn Something. Teach Something. Grow Together."
A complete, dependency-free web application designed for 2nd-year BTech Web Technology Lab exams.

Problem Statement & Solution

In engineering colleges, students often excel in specific domains—one might be brilliant at C++ and algorithms, another at Figma UI design, and another at playing acoustic guitar or calculus. However, traditional tutoring often involves financial barriers or unstructured favors.

SkillSwap solves this through a non-monetary, peer-to-peer barter network. Students list what they can teach and what they want to learn, and the platform pairs them for collaborative study sessions.

2nd-Year Lab Viva Questions & Answers

Use these concise, point-wise explanations during your external lab viva examination:

Q1: What is HTML5 LocalStorage and how is it used in this project?

Answer: LocalStorage is part of the Web Storage API that allows browsers to store up to 5MB of key-value string data persistently. Unlike cookies, data is not sent with every HTTP request. In SkillSwap, we use JSON.stringify() to store JavaScript arrays/objects under keys prefixed with skillswap_, and JSON.parse() to retrieve them.

Q2: How does the application run by simply double-clicking index.html without a server?

Answer: All links, scripts, and CSS references use relative file paths (e.g., css/base.css or ../js/storage.js). Browsers can open them using the file:/// protocol. Because no server-side compilation, Node.js, or backend API is used, the browser directly renders the HTML/CSS and runs JavaScript in the client-side sandbox.

Q3: How are passwords handled and why are they not stored?

Answer: In client-side static architectures without backend encryption or hashing, storing passwords in plain LocalStorage is insecure. In SkillSwap, password length and confirmation are validated in JavaScript to satisfy form validation requirements, but the password field is intentionally excluded from the stored user object, adhering to security lab guidelines.

Q4: How do the search and multiple filters work simultaneously in Explore?

Answer: The filterAndSortSkills() function chains JavaScript array methods (filter and sort). It takes the full array of skills, filters by keyword substring match (case-insensitive), filters by category and proficiency level, and then sorts by date, alphabetical name, or level hierarchy. The resulting array is rendered dynamically into the DOM using template literals.

Q5: How does the responsive design adapt to mobile phones?

Answer: Media queries at 1024px, 768px, and 480px dynamically adjust CSS Grid column counts (e.g., from 6 columns down to 3, 2, and 1). At 768px and below, the desktop navigation menu is hidden and replaced by a toggleable hamburger menu controlled by a lightweight JavaScript click listener that toggles the open CSS class.

Q6: How does the protected page route guard function?

Answer: The checkAuthGuard() function in auth.js checks if the current page filename is in a protected list (e.g., dashboard.html, add-skill.html). If isLoggedIn() returns false, it immediately redirects the browser to login.html using window.location.href.
